# 13 — Audio Units (outline, optional)

**This step is macOS only and has the lowest priority in the plan.**
mooloop is built for Linux users, and the Mac build exists for Adam's
convenience. Almost every AU plugin a Mac user owns also ships as CLAP or
VST3, and step 12 covers those. Do this step only if Adam asks for it after
step 12. (`REFERENCE_MEASUREMENTS.md` notes the reverse case: a UAD AU build
that doesn't scan while the VST3 build of the same plugin does.)

## Shape if it is done

- A module `au` in `mooloop-plugin-host`, `cfg(target_os = "macos")`, using
  the `objc2-audio-toolbox` bindings.
- **AUv2 in process** through `AudioComponentFindNext` /
  `AudioComponentInstanceNew`. AUv3 extensions run out of process and are
  harder; decide on them separately.
- **Parameters:** global-scope `AudioUnitParameterID`s map directly to the
  `u32` ids. Values are already plain.
- **State:** the `ClassInfo` property list, stored as one chunk.
- **Rendering:** `AudioUnitRender` with a pull callback that supplies the
  `StereoBus` as input. Scheduled parameter events for sample accuracy.
- **Scanning:** the component manager lists what is installed, and every
  candidate is still validated in the out-of-process child.
- **GUI:** `kAudioUnitProperty_CocoaUI` hosted in an `NSView` inside step
  11's window.
- **CI:** the existing macOS job builds and tests the module, using Apple's
  built-in AUs (`AUDelay`, `DLSMusicDevice`) as test plugins.
